Getting Started

Accessing the App

https://ai.phoenixhomeremodeling.net

Log in with the credentials in .env.local on the server (ADMIN_EMAIL / ADMIN_PASSWORD).

First Time Setup

  1. Log in and explore the 6 default agents on the Dashboard
  2. Go to Settings → Company Knowledge Base — upload your service catalog, pricing, FAQs
  3. Go to Settings → API Keys — generate a key for GHL or N8N
  4. Click any agent → Train tab → write a system prompt for that agent's role
  5. Go to Settings → Outbound Webhooks — add your N8N or GHL webhook URLs

Deleting an Agent

Open the agent → click the red Delete button in the top-left of the sidebar (next to "← All Agents"). Confirms before deleting. Removes all associated knowledge, memory, integrations, and schedules — tasks are preserved with a null agent reference.

The 6 default agents (research, code, data, writer, email, security) can be deleted but will not be re-created on restart.

Calling Integrations from a Task

Agents can call any configured integration or outbound webhook mid-task using the CALL pattern:

{{CALL:IntegrationName:{"key":"value"}}}

If the payload is empty {}, the system automatically injects the content the agent wrote before the CALL tag. Agents can make up to 3 calls per task.

Sub-agents

An agent can spawn a child agent mid-task:

{{SPAWN:agent_id:task description}}

The child runs to completion and its result feeds back to the parent automatically.

Task Actions

  • Cancel — red × button while running or pending
  • Copy — copy result to clipboard
  • Export — download result as a .md file
  • Project — assign to a project via dropdown
  • Refine — chat input appears after completion to iterate
  • Compact — appears after 4+ refine messages; summarises conversation to free context
Tasks auto-fail after 3 minutes via a global timeout. Streaming results appear word-by-word in real time.

Training an Agent

System Prompt

The core instructions that shape every response. Go to Agent → Train → System Prompt and save.

Knowledge Base (Files)

Upload PDFs, TXT, CSV, JSON, HTML, Markdown. Injected into every task the agent runs. Limit: 2MB per file. Re-uploading a file replaces the old version — no duplicates accumulate.

Google Drive Folders

Link Drive folders to an agent in the Train tab. Files sync into the knowledge base on demand. Supports Google Docs, Sheets, Slides, PDFs, Word docs, and plain text. Re-syncing a file replaces the old version. Requires Google OAuth in Settings.

Task Templates

Save reusable prompts with {{variable}} placeholders. Click Use → fill variables → dispatch.

Company Knowledge Base

In Settings → Company Knowledge Base — upload files shared automatically by all agents. Perfect for service catalogs, pricing, and FAQs. Limit: 5MB per file.

Knowledge base changes take effect immediately on the next task — no restart needed.

Outbound Webhooks

Configure in Settings → Outbound Webhooks. Two distinct ways they fire:

1. Automatic — on task events

Every time a task completes (or fails), Claude OS POSTs to all webhooks subscribed to that event:

{
  "event": "task.completed",
  "task_id": 42,
  "agent_id": "writer",
  "title": "Write follow-up email",
  "result": "Dear John...",
  "tokens_used": 850,
  "timestamp": "2026-06-09T14:22:11Z"
}

Available events: task.completed, task.failed, or both.

2. Agent-initiated — via CALL or chat

Agents (and the Hermes chat) can actively send content to any named webhook:

// From a task (agent uses CALL pattern)
{{CALL:Test Webhook:{"content":"The blog post text goes here"}}}

// From Hermes chat (uses send_webhook tool automatically)
"Write a blog post about kitchen remodels and send it to Test Webhook"

N8N will receive the payload in $json.body.content. Make sure the N8N webhook node is set to POST method.

The webhook must be saved in Settings → Outbound Webhooks before agents can call it by name.

Pipelines

Chain agents so the output of one step becomes the input of the next.

Step 1: Research Agent  → "Research top remodeling trends in Phoenix"
Step 2: Content Writer  → "Write a blog post based on the research above"
Step 3: Email Manager   → "Draft a newsletter from this blog post"
  • Use {{variable}} in step descriptions for dynamic inputs
  • Toggle "Pass previous step output" to feed results forward
  • Trigger via ▶ Run or API: POST /api/pipelines/[id]/run

Email Health Report

A full email deliverability and engagement analysis powered by GHL contact tags and workflow campaign stats. Go to 📧 Email Health in the sidebar.

Setup

GHL_API_KEY=pit-your-token-here
GHL_LOCATION_ID=your-location-id
GHL_DOMAIN=l.phxhomeremodeling.com

Date Range

Select a From and To date. Quick presets: This Month, Last 7d, Last 30d. Both dates are capped at today — future dates are disabled.

When a snapshot exists for the start date, the report shows delta stats (only what happened in that window). Without a snapshot it falls back to all-time totals.

Snapshots

Snapshots save the all-time campaign totals at a specific point in time. The delta between two snapshots equals the activity in that window — the basis for accurate date-range reporting.

How it works

  1. Generating a report automatically saves a snapshot for today — no manual action needed
  2. The 📸 button in the report toolbar opens the snapshot manager
  3. Take a snapshot manually any time with Take Snapshot Today
  4. Snapshots also run automatically every night at midnight

Running a delta report

  1. Generate a report today (auto-saves today's snapshot as baseline)
  2. Come back next week — set From = today's date, To = next week
  3. Click Generate — the report shows only what happened in that 7-day window

Managing snapshots

Click the 📸 N snapshots button to open the manager. Each snapshot shows its date and a Delete button. Deleting a snapshot means any report using it as a baseline will fall back to all-time totals.

If a campaign didn't exist at snapshot time (new campaign), the report shows its full current stats as the delta — which is correct since it had 0 sends at the baseline.

Troubleshooting

Task stuck on Running

Run the clear command above. Tasks auto-fail after 3 minutes via the global timeout.

Agent doesn't know about uploaded files

node -e "
const db = require('better-sqlite3')('data/claude-os.db');
console.log(db.prepare('SELECT agent_id,filename,length(content) as chars FROM agent_knowledge').all());
"

If chars is under 100 the file wasn't extracted properly. Re-upload it. PDFs need npm install pdf-parse. Re-uploading now replaces the old version cleanly — no duplicate accumulation.

Build fails

git fetch origin && git reset --hard origin/master && npm install && npm run build && pm2 restart claude-os

Email report shows all-time stats instead of date range

No snapshot exists for the selected start date. Generate a report first (auto-saves a snapshot for today), then use today's date as the start date in future reports.

N8N webhook body is empty

  • Make sure the N8N webhook node is set to POST method (not GET)
  • Make sure the webhook is saved in Settings → Outbound Webhooks
  • Test by asking Hermes: "Send [some text] to [webhook name]"
